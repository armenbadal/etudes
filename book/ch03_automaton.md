# Էտյուդ 1. Վերջավոր ավտոմատներ

Առաջին էտյուդում պետք է նախագծենք և իրականացնենք փոքր լեզու, որով 
հնարավոր կլինի նկարագրել դետերմինացված վերջավոր ավտոմատներ և 
դրանց օգնությամբ ճանաչել նիշերի հաջորդականություններ։

Այս խնդրի նպատակն է մի փոքր օրինակի վրա տեսնել լեզվի իրականացման 
ամբողջ ճանապարհը՝ գաղափարից մինչև աշխատող ծրագիր։ Պետք է սահմանենք 
լեզվի հնարավորությունները, նկարագրենք նրա շարահյուսությունը, իրականացնենք 
բառային ու շարահյուսական վերլուծիչները, կառուցենք ծրագրի ներքին ներկայացումը, 
ստուգենք նրա իմաստը՝ սեմանտիկան, և վերջապես կատարենք գրված ծրագիրը։


__Խնդիրը__

Ենթադրենք ուզում ենք նկարագրել այնպիսի ավտոմատ, որը ճանաչում է `a` և `b` 
նիշերից կազմված մեկ կամ ավելի նիշերի շղթա, որը պարտադիր վերջանում է `c` 
նիշով։ Օրինակ, `ac`, `abc`, `abbc`, `abababc` շղթաները պետք է ճանաչվեն, իսկ 
`c`, `ab`, `cab`, `abca` շղթաները՝ ոչ։ Այդ ավտոմատը կարող ենք նկարագրել 
հետևյալ կերպ.

```text
automaton EndsWithC {
    alphabet = {'a', 'b', 'c'}
    states = {start, body, final}

    initial = start
    finals = {final}

    transitions = {
        start, 'a' -> body;
        start, 'b' -> body;
        body, 'a' -> body;
        body, 'b' -> body;
        body, 'c' -> final;
    }
}

recognize "abababc" with EndsWithC;
recognize "cab" with EndsWithC;
```

Առաջին `recognize` հրամանը կճանաչի շղթան ու կարտածի «recognized», իսկ 
երկրորդը՝ չի ճանաչի ու կարտածի «not recognized»։ Այսպիսով՝ մեր լեզվում առայժմ 
կլինեն ընդամենը երկու գործողություն՝ վերջավոր ավտոմատի սահմանում և տրված 
ավտոմատով նիշերի հաջորդականության ճանաչում։

Թեև լեզուն փոքր է, այն արդեն ունի ծրագրավորման լեզուներին հատուկ որոշ 
հատկություններ՝ ծառայողական բառեր, անուններ, լիտերալներ, բլոկային կառուցվածք, 
սահմանումներ և անունների հետագա օգտագործում։ Դա բավական է լեզվի իրականացման 
հիմնական խնդիրների հետ առաջին անգամ ծանոթանալու համար։


__Վերջավոր ավտոմատը__

Դետերմինացված վերջավոր ավտոմատը սովորաբար ներկայացվում է \(M\) հնգյակով.

\[
M=\langle Q, \Sigma, \delta, q_0, F\rangle
\]

Այստեղ՝

- \(Q\)-ն վիճակների վերջավոր բազմությունն է,
- \(\Sigma\)-ն՝ ավտոմատի այբուբենը,
- \(\delta\)-ն՝ անցումների ֆունկցիան,
- \(q_0\)-ն՝ սկզբնական վիճակը,
- \(F\)-ը՝ վերջնական վիճակների բազմությունը։

Մեր լեզվի կառուցվածքները գրեթե ուղղակիորեն համապատասխանում են այս բաղադրիչներին.

| Ավտոմատի բաղադրիչ | Լեզվի կառուցվածք |
|---|---|
| \(\Sigma\) | `alphabet` |
| \(Q\) | `states` |
| \(q_0\) | `initial` |
| \(F\) | `finals` |
| \(\delta\) | `transitions` |

Օրինակ՝ `body, 'c' -> final;` անցումը նշանակում է, որ եթե ավտոմատը գտնվում 
է `body` վիճակում և ժապավենին տեսնում է `c` նիշը, ապա պետք է անցնի `final` 
վիճակին։

Այս լեզվում կընդունենք, որ անցումների ֆունկցիան մասնակի սահմանված է։ Եթե տվյալ 
վիճակի և նիշի համար անցում չկա, ապա ավտոմատը դադարեցնում է իր աշխատանքն
ու տրված հաջորդականությունը չի ճանաչում։


__Եվս մի ամբողջական օրինակ__

```text
automaton Binary {
    alphabet = {'0', '1'}
    states = {even, odd}

    initial = even
    finals = {even}

    transitions = {
        even, '0' -> even;
        even, '1' -> odd;
        odd, '0' -> odd;
        odd, '1' -> even;
    }
}

recognize "101101" with Binary;
recognize "111" with Binary;
```

Այս ավտոմատը ճանաչում է այն երկուական տողերը, որոնցում `1` նիշերի քանակը 
զույգ է։ `Binary`, `even`, `odd` անուններն ընտրում է ծրագրի հեղինակը. դրանք 
_իդենտիֆիկատորներ_ են։ Իսկ `automaton`, `alphabet`, `states`, `initial`, 
`finals`, `transitions`, `recognize`, `with` բառերը լեզվի մաս են և հատուկ 
նշանակություն ունեն. դրանք _ծառայողական բառեր_ են։


__Լեզվի շարահյուսությունը__

Շարահյուսական կանոնները գրված են Բեկուսի-Նաուրի ընդլայնված նոթագրությամբ։

```ebnf
Program = { Automaton | Recognition } .
Automaton = 'automaton' Identifier '{' Alphabet States Initial Finals Transitions '}'.
Alphabet = 'alphabet' '=' '{' Character { ',' Character } '}'.
States = 'states' '=' '{' Identifier { ',' Identifier } '}'.
Initial = 'initial' '=' Identifier.
Finals = 'finals' '=' '{' [ Identifier { ',' Identifier } ] '}'.
Transitions = 'transitions' '=' '{' { Transition } '}'.
Transition = Identifier ',' Character '->' Identifier ';'.
Recognition = 'recognize' String 'with' Identifier ';'.
```

Ավտոմատի բաղադրիչների հերթականությունը ֆիքսված է։ `alphabet`, `states`, `initial`, 
`finals`, `transitions` բաժինները պետք է գրվեն հենց այս հերթականությամբ։ 


__Ծրագրի ներքին ներկայացումը__

Այս փոքր լեզվի համար ընդհանուր նշանակության վերացական շարահյուսական ծառ 
կառուցելու կարիք չկա։ Բավական են երկու հիմնական կառուցվածքներ. մեկը հենց 
ավտոմատը ներկայացնելու համար, մյուսը՝ նիշերի շղթան ճանաչող հրամանը ներկայացնելու 
համար։ Ավտոմատի ներկայացումը հետևում է հենց շարահյուսությունից։

```text
+----------------------------+
| Ավտոմատ                    |
+----------------------------+
| այբուբեն: ցուցակ           |
| վիճակներ։ ցուցակ           |
| սկզբնական վիճակ։ անուն     |
| վերջնական վիճակներ։ ցուցակ |
| անցումներ։ ցուցակ          |
+----------------------------+
```

Անցումների ֆունկցիան որոշող ամեն մի տարրը եռյակ է.

```text
+----------------+
| Անցում         |
+----------------+
| որտեղից։ անուն |
| նիշ։ տառ       |
| ուր։ անուն     |
+--------------- +
```

Նիշերի շղթան ճաաչող հրամանը պարզապես մի զույգ է.

```text
+------------------+
| Ճանաչող          |
+------------------+
| նիշերի շղթա։ տող |
| ավտոմատ։ անուն   |
+------------------+
```

Ու վերջապես ծրագիր ներկայացումը, որ իր մեջ է հավաքում ավտոմատների ու ճակաչող 
հրամանների սահմանումները։

```text
+--------------------+
| Ծրագիր             |
+--------------------+
| ավտոմատներ։ ցուցակ |
| ճանաչողներ։ ցուցակ |
+--------------------+
```


__Բառակազմությունը__

Շարահյուսական վերլուծությունից առաջ ծրագրի տեքստը պետք է բաժանել բառային 
միավորների ու պիտակավորել դրանք։ Օրինակ.

```text
initial = start
```

տողի տարրերից առաջինին վերագրում ենք `INITIAL` պիտակը, երկրորդին՝ `EQUAL` 
պիտակը, իսկ երրորդին՝ `IDENTIFIER` պիտակը։

Ընդհանրապես, նայելով լեզվի շարահյուսությանը, կարող ենք տեսնել, որ բառային 
վերլուծության ժամանակ մեզ պետք են գալու հետևյալ պիտակները.

- _արժեքներ_ — `IDENTIFIER`, `CHARACTER`, `STRING`,
- _ծառայողական բառեր_ — `AUTOMATON`, `ALPHABET`, `STATES`, `INITIAL`, `FINALS`, `TRANSITIONS`, `RECOGNIZE`, `WITH`,
- _մետասիմվոլներ_ — `LEFT_BRACE`, `RIGHT_BRACE`, `EQUAL`, `COMMA`, `SEMICOLON`, `ARROW`,
- _տեքստի ավարտ_ — `END`,

Քանի որ ավտոմատների լեզվում մաթեմատիկական գործողություններ չկան ու կարիք 
չկա պարտադրելու, որ իդենտիֆիկատորները սկսվեն տաով ու պարունակեն միայն տառեր, 
թվանշաններ ու ընդգծման գիծ (ինչպես ընդունված է շատ ծրագրավորման լեզուներում), 
կարող ենք իդենտիվիկատորի սահմանումը բավականին ազատ պահել։ Օրինակ, իդենտիֆիկատորներ 
կարող են լինել `abc`, `x0`, `+ak+`, `first-automaton` և այլն։

Ավտոմատի այբուբենի տարրերը գրենք միակ չակերտների մեջ՝ `'a'`, `'0'`, `'+'`, իսկ 
`recognize` հրամանին փոխանցվող հաջորդականությունը՝ կրկնակի չակերտների մեջ՝ 
`"abba"`։


__Բառային վերլուծիչը__

_Բառային վերլուծիչը_ պետք է նիշ-առ-նիշ կարդա ծրագրիտեքստ ու առանձնացնի 
բառակազմական տարրերը՝ ամեն մեկին վերագրելով վերը թվարկված պիտակներից մեկը։ 
Այն պետք է նաև դեն նետի բառային իմաստ չկրող նիշերը, կարդա ու անտեսի 
մեկնաբանությունները, ինչպես նաև ազդարարի տեքստում չթույլատրված նիշերի 
առկայության մասին։

Ծառայողական բառերն ու իդենտիֆիկատորները հարմար է ճանաչել նույն եղանակով։ 
Նախ կարդում ենք իդենտիֆիկատորներում թույլատրելի նիշերի հնարավորինս երկար 
հաջորդականությունը, ապա ստուգում՝ արդյոք այն առկա է ծառայողական բառերի 
ցուցակում։ Եթե կա, վերադարձնում ենք համապատասխան պիտակըը, հակառակ դեպքում՝ 
`IDENTIFIER`։

Յուրաքանչյուր բառակազմական տարրի հետ, բացի պիտակը, հարմար է պահել նաև 
տեքստում դրա հանդիպելու դիրքը։ Սա շատ հարմար է սխալների մասին հաղորդագրությունների 
ձևավորման համար։


__Շարահյուսական վերլուծիչը__

Այսպիսի պարզ շարահյուսություն ունեցող լեզվի համար շատ հեշտ է իրականացնել թե 
ռեկուրսիվ վայրէջքի եղանակը, թե օգտագործել վերլուծիչների գեներատոր, ինչպիսին է, 
օրինակ YACC-ը կամ ANTL4-ը։ 

Եթե ընտրվում է ռեկուրսիվ վայրէջքի եղանակը, ապա ամեն մի շարահյուսական կանոնին 
համապատսխան պետք է սահմանել վերլուծող ենթածրագիր, ու դրանց ռեկուրսիվ կանչերով 
կազմակերպել ամբողջ շարահյուսական վերլուծությունը։

Օրինակ, `Initial = 'initial' '=' Identifier.` կանոնին համար գրված վերլուծող 
ենթածրագիրը պետք է տեսնի `INITIAL`, ապա `EQUAL`, հետո `IDENTIFIER` և վերադարձնի 
վերջին իդենտիֆիկատորի արժեքը։

Շարահյուսական վերլուծիչն էլ պետք է կարողանա հայտնաբերել ծրագրի կառուցվածքային 
սխալներն ու ցույց տա բովանդակալից հաղորդագրություններ։


__Իմաստային վերլուծությունը__

Երբ շարահյուսական վերլուծիչը հաջողությամբ վերլուծել է տրված ծրագիրն ու 
այն ներկայացրել է համաապատասխան օբյեկտներով, պետք է կատարել առնվազն հետևյալ 
իմաստային ստուգումները.

- ավտոմատի անունը պետք է եզակի լինի տրված ծրագրում,
- վիճակների անունները պետք է եզակի լինեն,
- այբուբենի նիշերը պետք է եզակի լինեն,
- վիճակների բազմությունը չպետք է դատարկ լինի,
- սկզբնական վիճակը պետք է վիճակների բազմությունից լինի,
- բոլոր վերջնական վիճակները պետք է հայտարարված լինեն,
- յուրաքանչյուր անցման սկզբնական ու վերջնական վիճակները պետք է հայտարարված լինեն,
- անցման նիշը պետք է պատկանի ավտոմատի այբուբենին,
- նույն `(վիճակ, նիշ)` զույգի համար պետք է լինի առավելագույնը մեկ անցում,
- `recognize` հրամանում օգտագործվող ավտոմատը պետք է սահմանված լինի։

Դետերմինացվածության կանոնը հատկապես կարևոր է։ Նույն վիճակի և նույն նիշի համար 
չի կարելի երկու տարբեր անցում սահմանել.

```text
start, 'a' -> left;
start, 'a' -> right;
```

Այստեղ արդեն ստուգում ենք ոչ միայն անունների գոյությունը, այլև ավտոմատի 
մաթեմատիկական հատկությունը։


__Ծրագրի կատարումը__

Եթե շարահյուսական ու իմաստային վերլուծության արդյունքում ծրագրում սխալներ 
չեն հայտնաբերվել, կարելի է այն կատարել։ Ավտոմատի աշխատանքի ալգորիթմը շատ 
պարզ է.

```text
state = initial

for symbol in input:
    transition = delta(state, symbol)

    if transition does not exist:
        return false

    state = transition.to

return state is final
```

Անցումները կարելի է պահել ցուցակով և յուրաքանչյուր քայլի ժամանակ հերթով 
փնտրել համապատասխան անցումը։ Առաջին իրականացման համար դա բավարար է։ 
Հետագայում կարելի է կառուցել վիճակ-սիմվոլ զույգը վիճակին արտապատկերող
աղյուսակ, որպեսզի անցումների ֆունկցիան դառնա ուղղակի որոնում ըստ բանալի 
զույգի։


__Սխալների հաղորդագրությունները__

Սխալ հայտնաբերելը աշխատանքի միայն մի մասն է։ Անհրաժեշտ է նաև ծրագիրը
գրողին բացատրել, թե ինչն է սխալ։ Օրինակ, `semantic error` հաղորդագրության 
փոխարեն կարելի է գրել.

```text
line 6: initial state 'begin' is not declared
```

կամ՝

```text
line 12: transition uses symbol 'c', which is not in the automaton alphabet
```

Հնարավորության դեպքում սխալի հետ պետք է պահել նաև սկզբնական ծրագրում 
համապատասխան կառուցվածքի դիրքը։


__Թեստավորում__

Լեզվի իրականացումը պետք է փորձարկել ոչ միայն ճիշտ ծրագրերով։ Անհրաժեշտ են 
առնվազն երեք տեսակի թեստեր։

_Բառային վերլուծության թեստերը_ պետք է ստուգեն ճիշտ token-ների հաջորդականությունը, 
ինչպես նաև սխալ նիշերը, չփակված տողերն ու նիշային լիտերալները։

_Շարահյուսական թեստերը_ պետք է տարբերեն, օրինակ, `initial = start` և `initial start` 
գրառումները՝ ընդունելով առաջինը և մերժելով երկրորդը։

_Իմաստային թեստերը_ պետք է առանձին օրինակ ունենան յուրաքանչյուր կանոնի համար՝ 
չհայտարարված սկզբնական կամ վերջնական վիճակ, անհայտ վիճակ անցման մեջ, այբուբենին 
չպատկանող նիշ, կրկնվող վիճակ, ոչ դետերմինացված անցումներ և գոյություն չունեցող 
ավտոմատի օգտագործում։

Վերջապես պետք է փորձարկել նաև ավտոմատի իրական աշխատանքը։ Առնվազն մեկ ավտոմատի համար 
ցանկալի է կազմել ճանաչվող և չճանաչվող տողերի բավական մեծ հավաքածու։


__AI գործիքների օգտագործումը__

Այս խնդիրը կարելի է ամբողջությամբ հանձնարարել AI գործիքին և արագ ստանալ աշխատող թվացող scanner, parser և interpreter։ Սակայն այս գրքի նպատակի տեսանկյունից դա առանձնապես օգտակար չէ։ AI-ին կարելի է հանձնարարել լրացուցիչ թեստային օրինակների և սխալ ծրագրերի գեներացում, scanner-ի սահմանային դեպքերի վերանայում, unit test-ների սկզբնական կմախքի կառուցում կամ սխալների ավելի օգտակար հաղորդագրությունների առաջարկում։

Լեզվի քերականությունը, իմաստային կանոնները և ծրագրի ներքին ներկայացումը ցանկալի է սկզբում նախագծել ինքնուրույն։ AI-ի գեներացրած կոդը նույնպես պետք է դիտարկել որպես ստուգման ենթակա կոդ։ Կարելի է, օրինակ, նրան տալ ավտոմատի կատարման մի իրականացում և խնդրել գտնել այնպիսի մուտքեր, որոնց դեպքում կոդը սխալ արդյունք է տալիս կամ վթարվում է, ապա ստուգել նաև այն դեպքերը, որոնք AI-ն բաց է թողել։

## Ինքնուրույն աշխատանք

Իրականացրեք այս գլխում սահմանված լեզուն։ Ծրագիրը պետք է կարողանա՝

1. կարդալ լեզվով գրված ծրագիր,
2. կատարել բառային վերլուծություն,
3. կատարել շարահյուսական վերլուծություն,
4. կառուցել ծրագրի ներքին ներկայացումը,
5. կատարել իմաստային ստուգումներ,
6. կատարել `recognize` հրամանները։

Սխալների հաղորդագրություններում հնարավորության դեպքում նշեք սկզբնական ծրագրի համապատասխան տողն ու սյունը։

## Լրացուցիչ առաջադրանքներ

1. **Մերժող վիճակ։** Մասնակի անցումների փոխարեն պահանջեք, որ անցումների ֆունկցիան ամբողջական լինի, կամ ավտոմատ կերպով ավելացրեք հատուկ մերժող վիճակ և բացակայող բոլոր անցումները ուղղեք դեպի այն։
2. **Դատարկ տողի ճանաչում։** Կազմեք ավտոմատ, որը ճանաչում է դատարկ տողը, և ստուգեք՝ interpreter-ը ճիշտ աշխատո՞ւմ է զրոյական երկարությամբ մուտքի համար։
3. **Գրաֆիկական ներկայացում։** Ավտոմատի նկարագրությունից գեներացրեք Graphviz DOT ֆայլ։ Այս դեպքում նույն ներքին ներկայացումը կօգտագործեն և՛ interpreter-ը, և՛ DOT գեներատորը։
4. **Բաժինների ազատ հերթականություն։** Թույլատրեք `alphabet`, `states`, `initial`, `finals`, `transitions` բաժինները գրել ցանկացած հերթականությամբ։ Որոշեք՝ ինչ անել, եթե մի բաժին բացակայում է կամ գրված է երկու անգամ։
5. **Ավտոմատների համեմատություն։** Ավելացրեք հրաման, որը նույն տողը ճանաչում է երկու տարբեր ավտոմատներով։ Սա կարող է բերել ավելի բարդ խնդրի՝ երկու վերջավոր ավտոմատների համարժեքության ստուգմանը։

## Ինչ ստացանք

Այս էտյուդում մենք դեռ չենք կառուցել ընդհանուր նշանակության ծրագրավորման լեզու։ Չունենք թվաբանական արտահայտություններ, փոփոխականներ, պայմանական հրամաններ կամ ֆունկցիաներ։ Բայց արդեն իրականացրել ենք ծրագրավորման լեզվի գրեթե ամբողջ հիմնական շղթան.

```text
source text
    ↓
scanner
    ↓
tokens
    ↓
parser
    ↓
program representation
    ↓
semantic analysis
    ↓
execution
```

Հետագա էտյուդներում այս սխեման նորից ու նորից կհանդիպի մեզ։ Կփոխվեն լեզուները, կբարդանան դրանց կառուցվածքները, կհայտնվեն արտահայտություններ, տիպեր, անունների տեսանելիության տիրույթներ և կոդի գեներացիա։

Բայց առաջին և ամենակարևոր քայլն արդեն արված է. մենք վերցրինք փոքր խնդրային տիրույթ, դրա համար նախագծեցինք լեզու և այդ լեզվի նկարագրությունը վերածեցինք աշխատող համակարգի։
